# Quick Start - x86-64 Assembly on Linux

## Fastest Way to Get Started (Docker)

### Method 1: Docker Compose (Recommended - Easiest!)

```bash
# Clone or navigate to the repository
cd /path/to/x86-asm

# Start the development environment
docker-compose run --rm asm-dev

# You're now in a Linux environment with all tools installed!
# Test it works:
cd 01-basics/01-hello-world
make solution
# Should print "Hello, World!"
```

**That's it!** All tools (nasm, make, gdb, vim) are pre-installed.

**To exit**: Type `exit` or press Ctrl+D

**To re-enter**: Just run `docker-compose run --rm asm-dev` again

---

### Method 2: Using Dockerfile

```bash
# Build the image once
docker build -t asm-dev .

# Run the container
docker run -it --rm --platform linux/amd64 \
  -v $(pwd):/code -w /code \
  asm-dev

# You're in! Test it:
cd 01-basics/01-hello-world
make solution
```

---

### Method 3: Plain Docker (No Build Required)

If you don't want to build anything, use the base Ubuntu image:

```bash
# Start Linux environment
docker run -it --rm --platform linux/amd64 \
  -v $(pwd):/code -w /code \
  ubuntu:22.04 bash

# Install tools (only needed once per session)
apt update && apt install -y nasm make gdb vim binutils

# Test it works
cd 01-basics/01-hello-world
make solution
```

## Your Workflow

### With Docker Compose (Recommended)

1. **Edit files on your host** (Mac/Windows/Linux) with your favorite editor (VS Code, Vim, etc.)
2. **Build and run in Docker**:
   ```bash
   docker-compose run --rm asm-dev
   cd 01-basics/01-hello-world
   make
   ./hello
   ```
3. **Exit**: `exit` or Ctrl+D
4. **Your files persist** on your host machine

### Quick Scripts

Create `dev.sh` in the repository root:
```bash
#!/bin/bash
docker-compose run --rm asm-dev
```

Then:
```bash
chmod +x dev.sh
./dev.sh          # Enter your dev environment anytime!
```

Or create `dev-shell.sh` for direct bash access:
```bash
#!/bin/bash
docker-compose run --rm asm-dev bash
```

## Quick Command Reference

### Inside Docker Container

```bash
# Build and run
make            # Build your code
make run        # Build and run
make solution   # Build and run the solution
make test       # Run automated tests
make clean      # Clean up build artifacts

# Manual build
nasm -f elf64 program.asm -o program.o
ld -o program program.o
./program

# Check exit code
echo $?

# Debug
nasm -f elf64 -g program.asm -o program.o
ld -o program program.o
gdb ./program
```

### GDB Commands

```bash
(gdb) break _start      # Set breakpoint
(gdb) run               # Start program
(gdb) stepi             # Step one instruction
(gdb) info registers    # View all registers
(gdb) x/s $rsi          # Examine string at rsi
(gdb) continue          # Continue execution
(gdb) quit              # Exit GDB
```

## What Gets Installed

The Docker environment includes:
- **nasm** - The Netwide Assembler
- **ld** - GNU linker (from binutils)
- **make** - Build automation
- **gdb** - GNU debugger
- **vim** - Text editor (for quick edits)
- **strace** - System call tracer
- **file** - File type identification
- **binutils** - Binary utilities (objdump, readelf, etc.)

## Troubleshooting

### "Cannot connect to Docker daemon"
Make sure Docker Desktop is running.

### "Platform mismatch" warnings
The `--platform linux/amd64` flag ensures x86-64 compatibility, even on ARM Macs (M1/M2/M3).

### Files not showing up in Docker
Make sure you're running Docker from the repository directory where you have your .asm files.

### Permission denied when running programs
```bash
chmod +x ./program
```
